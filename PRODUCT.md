# Product

## Register

product

## Users

Museum operators use the browser console during live visitor conversations. They need to capture one response at a time without losing track of the current visitor or the next keyboard action.

## Product Purpose

Event Lens captures visitor audio, accepts or discards each response, and sends accepted recordings through the transcription pipeline. The browser UI should make the live capture state and next action obvious at a glance.

## Brand Personality

Modern and classic, with calm operator confidence. The interface should feel considered and familiar, not like a desktop terminal or a decorative audio toy.

## Anti-references

Avoid desktop-app chrome, terminal-like layouts, neon dashboard styling, dense analytics panels, and controls that hide the save, pause, retry, and stop-capture flow.

## Design Principles

- Make the current visitor and current recording state unmistakable.
- Keep the browser workflow focused on one decision at a time.
- Make Enter, Escape, Q, start-recording, and save-and-pause behavior visible in the interface.
- Use established accessible components instead of reimplementing interaction primitives.

## Accessibility & Inclusion

The browser UI must work with keyboard controls and visible focus states. Preserve readable contrast, touch-sized controls, semantic labels, and reduced-motion behavior. No additional accessibility requirements were provided; use WCAG AA as the baseline.
